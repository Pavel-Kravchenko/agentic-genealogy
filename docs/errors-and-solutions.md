# Errors and solutions

A short index of the traps described in the method guides, the resource guides and the skills, as symptom,
cause and fix. Each row points to the guide that explains the trap and its context; read the guide before
acting on a row. Find your symptom by the section and the first column.

The examples are composed illustrations; the patterns come from real work, the particulars do not. Site
observations date from August to November 2026. Sites change: recheck a site's behaviour before relying on a
row about it. Sites that need a login, a subscription or a captcha are used by the researcher personally, in
their own browser, and agents do not use them.

## Searching and evidence

| area | symptom | cause | fix | guide |
|---|---|---|---|---|
| search results | an empty result page is recorded as "not found" | the site refused the request, and a refusal looks like an honest zero | record three outcomes (result, true zero, block); a zero counts only when the site's own "nothing found" marker is present | [block-vs-zero.md](method/block-vs-zero.md) |
| search results | status 200 and no records | most refusals come back as status 200: a very small page, a login form, a challenge page | judge by the size and type of the body and the marker text, not by the status code | [block-vs-zero.md](method/block-vs-zero.md) |
| search results | a search page read without a browser shows an empty shell | the results are drawn in the browser | neither a zero nor a block; search it in a browser | [block-vs-zero.md](method/block-vs-zero.md) |
| search results | a long result list that does not change with the query | the site ignored a search term and returned the whole collection | test with two different queries; record "search does not work" and treat it as not run | [block-vs-zero.md](method/block-vs-zero.md) |
| control queries | zeros are trusted that later prove false | no proof that the search ran | run a control query that must return records (a common surname) in the same session; if it returns nothing, every zero of that session is void | [README.md](resources/README.md) |
| downloads | a saved image does not open; several "images" have the same size and checksum | an HTML error page or a login form was saved under an image name | check the format signature at both ends (JPEG `FF D8 FF` ... `FF D9`, PDF `%PDF`), not the status or the size | [block-vs-zero.md](method/block-vs-zero.md) |
| pacing | refusals start soon after a search begins | several agents on one domain multiply the request rate without anybody seeing the total | one site, one agent, one request at a time, slowly; stop at the first refusal and never retry in a loop | [block-vs-zero.md](method/block-vs-zero.md) |
| site down | no connection, a 5xx error or a broken certificate | the site is down | mark the question "not checked", never "absent"; try again on another day | [block-vs-zero.md](method/block-vs-zero.md) |
| page tools | a wrong postal address or number read from a page | a fetch tool mis-decoded a page in a legacy encoding (cp1251) or summarised it | read the page itself and decode it explicitly (`iconv -f cp1251`); take addresses, shelf marks and numbers only from the page; a search engine's answer is not a source either | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| full-text index | spelling variants give separate, non-overlapping lists; an unrequested form holds a family member | a lemmatising index treats distorted roots as different words | vary the distortions of the root, not the grammatical cases; test two case forms of the surname first | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| full-text index | a prefix or truncated query returns unrelated hits | truncation does not work as a prefix in an index that matches word forms | query full word forms; test truncation on a known hit before relying on it | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| full-text index | a full name returns an enormous number of hits | the index does not join the words of a query with AND | query one rare word form | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| early registers | no hits by surname before the mid-1880s | peasant entries mostly carry no surname | search given name + patronymic + wife's name, or the farm name | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| OCR | the year of a leaf is wrong in the last digit or the decade | machine reading loses the handwritten digit on a printed form | take the year from the duplicate copy or the dating of the file, not from the printed header | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| OCR of typescript | a search by file number or name misses a file known to be there | OCR of carbon copies turns `3` into `5` or `8`, `Ж` into `Л`, and drops smudged lines | search with tolerant patterns and short stems; reconstruct a file number from its neighbours; check the image | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| OCR text | a text search finds nothing in downloaded OCR | words are broken by spaces and hyphens | put `[\s\-]*` between the letters of the pattern | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| OCR of tables | a revision list gives plausible but wrong ages and years | the text layer mixes up the order of rows | sort the recognised blocks by horizontal position into columns, then by vertical position; check doubtful cells on a crop of the image | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| namesake places | the result list is full of a namesake place | the same name exists in another commune or province | filter by the word for the higher unit as printed (for example the county in the genitive), not by the place name | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| query narrowing | a phrase query returns about half of what one word returns | phrase matching drops records | search one word and filter locally; draw no negative conclusion from a phrase query | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| catalogues | a file is not found by its year | the catalogue gives a range of years | expand ranges; never search a literal year in headings | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| viewers | a leaf reference is off by a few | a frame number in a viewer is not a leaf number | cite leaves from the image; record frame, leaf and viewer index separately | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| snippets | a wrong patronymic, "months" for "years", two families merged | a search snippet is machine markup | copy no fact from a snippet; read the scan | [reading-indexes-and-ocr.md](method/reading-indexes-and-ocr.md) |
| documents | a fact taken from an index, a catalogue line, a tree or a memory | these say where to look; none of them is the fact | a fact enters the record from a document image, with its shelf mark | [evidence-rules.md](method/evidence-rules.md) |
| identity | a file ordered as "ours" belongs to a man of the same full name | name, given name and patronymic used as an identifier | a file belongs to the family when the volost and the estate match, not the name | [evidence-rules.md](method/evidence-rules.md) |
| identity | two namesake women merged because their ages were close | age in a questionnaire is weak by construction | compare household members, then parish or estate, then confession, and only then dates and ages | [evidence-rules.md](method/evidence-rules.md) |
| identity | a document's people merged into existing persons without proof | identity was assumed | enter them as separate persons with "presumed kinship", confidence low; do not touch the existing person's dates | [evidence-rules.md](method/evidence-rules.md) |
| dates | a disputed date "corrected" to match another source | smoothing without a new document | keep both values with their sources; where a document disagrees with a gravestone or a memory, print both | [evidence-rules.md](method/evidence-rules.md) |
| dates | a tree date differs from the register date | the tree gives the date the act was registered | prefer the register for the event; write both when event and registration differ | [evidence-rules.md](method/evidence-rules.md) |
| kinship | a kinship computed from the graph contradicts a living relative | the graph, often built from somebody else's tree, was used as judge | record the kinship as stated, by whom; if a calculation is needed, ask one plain question | [evidence-rules.md](method/evidence-rules.md) |
| places | an archive answers "nothing" for a person who was there | the request used the place as named in a Soviet-era form, in the grid of the day it was filled in | fix the name of the place for the year of the event from the period lists of populated places | [evidence-rules.md](method/evidence-rules.md) |
| places | a village is missing from the period list of populated places | settler colonies were often listed as estates | look in monographs on the settlers and for the estate name | [libraries-and-reference.md](resources/libraries-and-reference.md) |
| negative claims | "not in the project" for a person who is in the graph | the graph was not searched; per-person sheets are incomplete | search the full person file by surname and given-name tokens before saying the project lacks something | [evidence-rules.md](method/evidence-rules.md) |

## Dead ends and false trails

| area | symptom | cause | fix | guide |
|---|---|---|---|---|
| ledger | the next session runs the same searches again | zeros were not recorded | keep `DEAD_ENDS.md` and read it before any search is planned; each agent brief names the entries that cover its ground | [dead-ends.md](method/dead-ends.md) |
| ledger entries | "he is nowhere" turns false within a week | an index covers one genre of record, not a person | write every negative in five parts: what, where (with genre), how much, result, what it means and what it does not mean | [dead-ends.md](method/dead-ends.md) |
| ledger entries | a technical lock read later as absence of a document | the entry carries no marker | start each entry with `[FINAL]`, `[CONDITIONAL · removable]`, `[CONDITIONAL · genre]` or `[TECHNICAL]` | [dead-ends.md](method/dead-ends.md) |
| ledger entries | a zero cannot be told from a block a year later | no proof that the tool worked at the time | put a control from the same session next to every zero; without it the entry is `[TECHNICAL]` | [dead-ends.md](method/dead-ends.md) |
| ledger entries | all zeros weigh the same | corpora differ in what they can hold | give each zero a weight (zero, low, medium, meaningful) and say why; war databases weigh zero for a person born long before | [dead-ends.md](method/dead-ends.md) |
| ledger upkeep | a closed entry contradicts a new fact | the ledger was not updated when the fact entered | strike the old text through, add a dated line below, name the evidence and why the old conclusion was wrong, update the marker table and every entry that cited it | [dead-ends.md](method/dead-ends.md) |
| planning | a wave is planned from the ledger | the ledger removes ground; it does not assign it | plan only from `OPEN_QUESTIONS.md`, and check every candidate step against the ledger | [dead-ends.md](method/dead-ends.md) |
| genre verdicts | a genre is declared "never names people" | only one subfamily of notices was read | check every subfamily before a verdict on a genre | [dead-ends.md](method/dead-ends.md) |
| outages | a database returns zero where it returned records the day before | an outage returned zero for every query | void all zeros of those days; rerun with a known-record control | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| spelling | zero under the "correct" surname | the oldest layer exists only under a sibilant or other variant | search every variant and record which were tried; the untried ones are the condition for reopening | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| spelling | a report says "no files for X" | the archive inventory normalised the spelling | search the archive's normalised form as well | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| spelling | a man is not found under the family surname | he was registered under a surname formed from his grandfather's name | add the grandfather's name to the variants | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| jurisdiction | zero for a village under its volost | the village belonged to another volost until some date | search under the unit of that year; do not carry the correction to neighbouring villages without checking | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| archive replies | "not searched" recorded as "not found" | the archive searched one confession and asked about the others | record "not searched" separately from "not found" | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| namesakes | a record matches given name, surname, village and an age within a year | a namesake in the same parish | check father's name and status, marital state, household, church, the column a line sits in; record the discriminator in the ledger | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| circular confirmation | two sources agree | the second descends from the first: a tree, an inscription without its own source, a printed tree exported from your own graph, a memory taken from a tree | count channels, not mentions; find the common origin of two "independent" confirmations | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| candidates | a candidate kept for a long time on an age match | approximate ages and common names | an age match keeps a candidate on the list and never promotes it; require a second identifier or a mechanism (nobody is older than his father's marriage) | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| catalogues | a file's title promises exactly what you need, and the pages show something else | catalogue misdescription (a registry fond holding church registers, transport lists taken for personal files) | order and cite a file by what its pages show; record the correction in the ledger | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| briefs | a wrong conclusion reappears in every brief | it lives only in a report and in briefs | write the correction into a reference file; briefs cite the ledgers, never another brief | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| geocoders | one place node on many events, far from the real places | a tree service's geocoder replaced the places | do not trust coordinates of pre-war persons; restore places only from the original note; never fill an empty place with an inferred value | [invalid-zeros-and-false-trails.md](method/invalid-zeros-and-false-trails.md) |
| dead sites | a link to an archive leads to a page that is no longer the institution's site | the domain changed hands | do not open or cite it; remove the links; cite the institution and its current address, or write to it | [dead-and-moved.md](resources/dead-and-moved.md) |
| dead sites | a domain that does not resolve is filed as "never existed" | a DNS failure is technical, not proof of absence | classify dead addresses as technical, final or conditional; try the web archive | [dead-and-moved.md](resources/dead-and-moved.md) |
| dead sites | agents check websites that never existed | reports, snippets and language models invent plausible domains | check against the list of never-existing addresses; record them as final | [dead-and-moved.md](resources/dead-and-moved.md) |

## Transcription

| area | symptom | cause | fix | guide |
|---|---|---|---|---|
| resolution | many `[illegible]` marks; most images exactly 1280 px on the long side | a messenger compressed images sent "as a photo" | check resolution before reading; ask for a re-shoot sent "as a file" or "as a document"; a line of cursive needs at least 100 px of height | [transcription.md](method/transcription.md) |
| photographing | cursive breaks up | a whole open book in one frame | one page per frame, page filling the frame, camera parallel, sheet flattened, diffuse light, no flash | [transcription.md](method/transcription.md) |
| photographing | pale ink vanished | the "document", "black and white" or "enhance" filter of a scanner app | shoot without filters; raise contrast later, reversibly | [transcription.md](method/transcription.md) |
| orientation | a page is shown sideways after rotating it | the pixels were rotated but the EXIF orientation tag was kept, so the viewer rotated again | `PIL.ImageOps.exif_transpose` instead of rotating pixels | [transcription.md](method/transcription.md) |
| PDFs | text extraction returns nothing from scanned letters | scanned PDFs have no text layer | take the raster out as is (`pdfimages -all`) or render the page (`pdftoppm -r 300`) | [transcription.md](method/transcription.md) |
| reading | a whole-page reading misses lines | too few model patches per letter | cut the page into overlapping strips (eight, 20 % overlap, contrast raised, about 1500 px wide); for a hard word crop one line at full resolution and enlarge it | [transcription.md](method/transcription.md) |
| reading | a confident second reader "corrects" a right first reading | reader confidence treated as evidence | close a disagreement by a third look at the image, not by a vote or by seniority | [transcription.md](method/transcription.md) |
| reading | a village or volost name that never existed | letters read and not checked | check every place name against a gazetteer of the period before it enters the graph | [transcription.md](method/transcription.md) |
| reading | a double date in a Lutheran personal register read as Old and New Style | the gaps vary, which no calendar does: they are birth and baptism | take the first date as birth; test whether the gap is constant (12 days, 13 from 1 March 1900) | [transcription.md](method/transcription.md) |
| marking | a plausible name replaces what is written | names corrected to something likely | write what is visible and mark it `[?]`; what is marked "probably" stays out of the book text | [transcription.md](method/transcription.md) |
| audio | the machine went down; the model cache holds only a configuration file | the large model exhausted the machine's memory | the turbo model, one file at a time, each result written at once, reruns skip finished files | [transcription.md](method/transcription.md) |
| audio | one recognition error repeats through a whole file | the model conditions on its previous text | `condition_on_previous_text=False`, and an `initial_prompt` with the expected surnames and places | [transcription.md](method/transcription.md) |
| audio | a forwarded `.m4a` does not open ("moov atom not found") | two bytes (`\r\n`) put in front of the file by the forwarding path | check the first bytes (`xxd -l 16`); `tail -c +3 file > copy`; the content is intact | [transcription.md](method/transcription.md) |
| audio | a transcript edited to match a register | the transcript treated as a draft | never edit the transcript; list recognition errors and disagreements with documents in a separate report | [transcription.md](method/transcription.md) |
| coverage | "untranscribed" frames are already transcribed | a messenger saved album photos twice under two names | count by checksum, not by file name | [transcription.md](method/transcription.md) |

## Family graph and GEDCOM

| area | symptom | cause | fix | guide |
|---|---|---|---|---|
| outputs | a correction made in a book, sheet or GEDCOM file disappears | outputs are regenerated from the graph | edit only the graph; never correct a generated reference list by hand | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| notes | a "cause of death" field swallows the place of burial and an address | notes joined with a tab or a full stop | join notes with `; ` only | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| rollback | restored values vanished | a rollback to a snapshot silently undoes every later step | after a rollback replay each later step from the journal, not from memory | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| changes | the same change applied twice | the change could be run twice | dry run by default; `--apply` takes a snapshot first; a second run refuses ("node already exists") | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| changes | disproved links still in the graph | an agent reported a removal and did not carry it out | check the removals an agent proposed, not only its additions | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| duplicates | most new nodes are duplicates after an entry | the search used the expected id prefix; an importer stored the family under its own ids, some without a surname | search by name tokens and by full date across the whole graph; run the duplicate finder before entering | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| merging | a child with two mothers after a merge; the invariant check refuses | links were re-pointed without removing the wrong one | remove the wrong link in the same step and run the checks | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| checks | nearly all "errors" are legitimate open values | state lines mixed with structure errors | report errors, findings and state separately; only errors fail the run | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| GEDCOM export | export fails on `after 1925` after a green run | the run passed only because the forms "before" and "after" were not yet in the data | check a tool by reading its code against every form you will enter | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| GEDCOM import | date qualifiers silently lost | the calendar escape stood after the qualifier (`ABT @#DJULIAN@ 1840`) and was removed only at the start of a value | parse the escape wherever it stands | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| GEDCOM export | Julian dates are not machine-readable on the target site | the exporter wrote no calendar escape, only a note | search the output for `@#D`; check what a round trip through each service keeps | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| GEDCOM export | living people in an exported file | the exporter does not filter them | remove them from a copy of the graph before exporting, by the family's rule | [maintaining-the-family-graph/SKILL.md](../plugins/genealogy/skills/maintaining-the-family-graph/SKILL.md) |
| file names | files one level too deep; a folder name cut at "(1850" | a `/` in a disputed year became a path separator | sanitise `/` (and `:` on macOS) in any name built from data; write "1850 or 1853" | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |
| file names | a pattern over file names matches nothing; a coverage check misses files discussed in the text | macOS returns names in NFD, literals are NFC | `unicodedata.normalize("NFC", ...)` on both file names and paths before comparing | [family-graph-and-gedcom.md](method/family-graph-and-gedcom.md) |

## Agent waves

| area | symptom | cause | fix | guide |
|---|---|---|---|---|
| reports | finds lost when agents died on API errors | results were held in context until the end | create the report first with `Status: IN PROGRESS`; append each finding at once with its shelf mark | [agent-waves.md](method/agent-waves.md) |
| reports | agents died on "Now writing the full file" with an empty skeleton on disk | one final write of the whole file | write section by section, never the whole file in one command | [agent-waves.md](method/agent-waves.md) |
| tool calls | an agent waits for a notification that never comes | it was started in background mode | synchronous calls only, each shell call with an explicit timeout | [agent-waves.md](method/agent-waves.md) |
| concurrency | some tasks silently never start | the harness ceiling on concurrent subagents was exceeded | launch in batches of 8-10 and keep the queue explicit | [agent-waves.md](method/agent-waves.md) |
| rate limits | running agents fail together | the session rate limit, shortly after a second batch started | wait for the reset, then resume; start the second batch as the first finishes | [agent-waves.md](method/agent-waves.md) |
| tool quotas | web search is silently empty for several agents | the search budget is per session and shared by the wave | budget searches per wave in the briefs; read pages directly where that will do | [agent-waves.md](method/agent-waves.md) |
| budget | a wave runs out of the usage limit or the coordinator's context | the wave was launched too late | with less than a fifth of the limit or of the context left, do not launch; write the briefs and start from a fresh session | [agent-waves.md](method/agent-waves.md) |
| status | a task reported `failed` while its file is almost complete | the status was trusted over the disk | read the disk first; never retell a result before its file has been read | [agent-waves.md](method/agent-waves.md) |
| dead agents | a restart costs several times the first run | the dead agent was restarted from zero | resume it by message in its own context: where it died, what is on disk, what remains | [agent-waves.md](method/agent-waves.md) |
| stale tasks | a wave spends its budget on questions closed weeks earlier | a stale open-questions list | strike closed lines the same day with the date and the report that closed them; clean the list before a wave | [agent-waves.md](method/agent-waves.md) |
| stale tasks | a full pass repeated over a corpus already read | the task quoted an old summary | open and search the current file on disk before running the pass | [agent-waves.md](method/agent-waves.md) |
| briefs | agents rediscover known traps and burn their request budget | the brief pointed to an earlier brief | put the protocols, the traps and an explicit do-not list into each brief | [agent-waves.md](method/agent-waves.md) |
| access | an agent was given a logged-in browser | the researcher's browser lent to the wave | no logged-in browser for agents; sites behind a login, a subscription or a captcha go to the researcher's queue | [agent-waves.md](method/agent-waves.md) |
| shared files | agents edit the graph or the summary files | no single writer | agents write only their own new files and propose graph changes; the coordinator merges | [agent-waves.md](method/agent-waves.md) |
